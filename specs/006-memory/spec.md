# Feature Specification: 三层 Memory 核心能力

**Feature Branch**: `022-lesson22-memory`

**Created**: 2026-08-27

**Status**: Implemented — verified

**Input**: User description: "第22节需求：为 Agent 提供统一、可持久且可控的记忆能力；核心阶段使用本地文件保存核心与归档长期记忆，复用既有会话历史，由 Agent 主动保存并按关键词回忆，不引入结构化长期记忆、外部记忆服务或语义检索。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 跨会话保留关键偏好 (Priority: P1)

用户告诉 Agent 一项需要长期保留的身份、项目背景或关键偏好。Agent 判断值得记忆并保存后，即使用户新开会话或重启 OryxOS，Agent 仍能在后续回复中使用该信息。

**Why this priority**: 跨会话记住用户是 Memory 区别于普通多轮聊天的首要价值，也是后续日报 Demo 能体现用户偏好的基础。

**Independent Test**: 保存一条核心记忆，重新加载运行时并创建新会话；新的上下文仍完整包含该记忆，即可独立证明跨会话持久化价值。

**Acceptance Scenarios**:

1. **Given** 工作区已经初始化且没有该偏好，**When** Agent 将偏好保存为核心记忆，**Then** 下一轮上下文完整包含该偏好。
2. **Given** 核心记忆已经保存，**When** OryxOS 重启并创建新会话，**Then** 核心记忆仍完整存在并可用于回复。
3. **Given** 归档内容增长到超过允许注入的上限，**When** 构建新一轮上下文，**Then** 核心记忆一字不丢，只有较早的归档内容被裁去。

---

### User Story 2 - 主动归档并按关键词回忆 (Priority: P1)

Agent 能在对话过程中主动保存值得长期保留的事实，并在后续任务中按关键词找回相关归档；系统不替 Agent 猜测哪些内容需要保存。

**Why this priority**: 主动保存和按需回忆构成长期记忆的最短闭环，避免核心阶段额外模型调用和不可审计的自动提炼。

**Independent Test**: 保存多条核心与归档记忆后按关键词检索；只返回归档区内匹配项，未命中给出稳定的空结果提示，即可独立验证。

**Acceptance Scenarios**:

1. **Given** Agent 未显式指定记忆范围，**When** 保存一条长期记忆，**Then** 该记忆进入归档范围。
2. **Given** Agent 显式选择核心范围，**When** 保存一条记忆，**Then** 该记忆进入核心范围且不会出现在归档检索结果中。
3. **Given** 归档范围存在多条内容，**When** 按关键词回忆，**Then** 仅返回包含该关键词的归档条目。
4. **Given** 没有匹配项，**When** Agent 回忆关键词，**Then** 得到“没有找到相关记忆”的可用结果而不是异常。

---

### User Story 3 - 统一组装本轮记忆上下文 (Priority: P2)

运行时在每轮推理前，通过统一记忆能力取得长期记忆和当前会话的最近历史，使 Agent 同时掌握稳定偏好与正在进行的任务，而调用方不需要了解持久化细节。

**Why this priority**: 统一上下文保证 Memory 真正进入 ReAct 主链路，同时保持引擎与具体存储解耦；它建立在长期记忆读写已可用的基础上。

**Independent Test**: 构造包含长期记忆和超长会话历史的场景；本轮上下文按固定顺序包含完整核心记忆、受限归档记忆及最近会话消息，且消息角色保持不变，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 长期记忆和会话历史均存在，**When** 组装本轮上下文，**Then** 长期记忆位于会话历史之前，最近会话消息保持原角色与顺序。
2. **Given** 会话历史超过配置上限，**When** 组装上下文，**Then** 只保留最近的消息，长期核心记忆不受影响。
3. **Given** 长期记忆为空，**When** 组装上下文，**Then** 不产生无意义的空记忆段，既有身份、Bootstrap、日期时间和工具声明行为不变。

### Edge Cases

- 工作区或记忆文件尚不存在时，初始化过程创建标准核心/归档分区；非初始化运行缺少工作区时给出明确错误，不写到其他路径。
- 文件只存在一个分区、分区顺序错误或内容为空时，系统不得把核心内容误当归档截断，也不得覆盖已有内容。
- 保存内容为空白、scope 非法或检索关键词为空白时，系统拒绝请求并返回明确、稳定且不泄漏本地路径的错误。
- 同一进程内多个保存请求接近同时发生时，已成功返回的记忆不得互相覆盖或丢失。
- 归档区恰好等于或刚超过 4000 字时，边界行为必须稳定；裁剪后保留最近内容。
- 用户维护的 Bootstrap 偏好文件始终只读，任何记忆写入不得修改它。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 向运行时提供单一稳定的记忆能力边界，调用方不得依赖长期记忆的文件路径、分区解析或写入细节。
- **FR-002**: 系统 MUST 将长期记忆分为核心和归档两个范围，并在同一工作区内跨会话、跨重启保留。
- **FR-003**: 系统 MUST 在首次初始化时建立核心与归档两个标准分区，并保留已有合法内容。
- **FR-004**: 系统 MUST 为每条新增长期记忆记录保存日期，并将未显式指定范围的保存请求路由到归档范围。
- **FR-005**: 系统 MUST 允许 Agent 显式把记忆保存到核心或归档范围，不得自动猜测或后台提炼会话内容。
- **FR-006**: 系统 MUST 在每轮上下文中完整提供全部核心记忆，任何归档裁剪不得改变核心内容。
- **FR-007**: 系统 MUST 将注入上下文的归档内容限制为最近 4000 字，并在超过上限时舍弃较早内容。
- **FR-008**: 系统 MUST 每次构建上下文或执行回忆时重新读取长期记忆，使成功保存的内容在下一次读取立即可见。
- **FR-009**: 系统 MUST 仅在归档范围执行大小写保持的包含式关键词检索，并按文件中的先后顺序返回匹配条目。
- **FR-010**: 系统 MUST 在关键词无匹配时返回稳定的“没有找到相关记忆”结果，不得把无结果当作系统异常。
- **FR-011**: 系统 MUST 将长期记忆与当前会话最近历史统一提供给本轮推理，并保持会话消息原有角色和顺序。
- **FR-012**: 系统 MUST 使用现有的会话历史上限；超过上限时只保留最近消息，不创建第二套 Session 或身份拼接规则。
- **FR-013**: 系统 MUST 通过 `save_memory` 与 `recall_memory` 两项声明式能力向获授权的 Agent 提供保存和回忆，并继续复用既有统一工具执行与审计路径。
- **FR-014**: 系统 MUST 保证用户维护的 Bootstrap 偏好资产只读，所有 Agent 产生的长期记忆只进入受控记忆区域。
- **FR-015**: 系统 MUST 对空白内容、空白关键词、非法范围、不可读写文件和畸形分区给出明确失败，不得静默成功或覆盖其他工作区文件。
- **FR-016**: 系统 MUST 在同一运行实例的并发保存中避免成功写入互相覆盖或丢失。
- **FR-017**: 核心阶段 MUST NOT 新增长期记忆数据表、后端选择配置、外部记忆服务、自动抽取、语义/向量检索、知识图谱、Memory Wiki、记忆压缩或内容缓存。
- **FR-018**: 系统 MUST 保持既有九模块数量与 ReAct、Session、Tool 和审计公共契约兼容；经批准的职责调整仅限核心记忆端口归属，不形成循环依赖。

### Key Entities

- **长期记忆条目**: Agent 主动保存的内容，具有核心或归档范围及保存日期；核心条目始终在场，归档条目可检索并受注入上限约束。
- **记忆上下文**: 本轮推理可见的长期记忆与最近会话历史组合；长期记忆在前，会话消息保留角色与顺序。
- **记忆范围**: 核心或归档的二值分类；缺省为归档，非法值不被接受。
- **会话历史**: 既有 Session 中累积的消息，按已有上限保留最近内容，不由本特性创建新的持久化模型。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的成功保存操作在下一次上下文构建和关键词回忆中立即可见，无需重启或等待失效周期。
- **SC-002**: 在归档内容超过 4000 字的所有边界测试中，核心记忆保持逐字完整，且最近归档内容被保留。
- **SC-003**: 重启后创建新会话时，已保存的长期记忆 100% 可恢复，用户无需重新输入偏好。
- **SC-004**: 关键词检索对归档测试数据的预期命中与未命中结果达到 100% 一致，核心条目不会混入检索结果。
- **SC-005**: 会话历史超过上限时，100% 保留最近消息的角色与顺序，且不影响长期记忆。
- **SC-006**: 所有非法输入、缺失工作区、文件读写失败和畸形分区场景均以明确失败结束，0 次静默覆盖用户维护资产。
- **SC-007**: 既有 Provider、ReAct、CLI/Session、Notify 与 Tool 自动化回归保持全部通过，且九模块数量不变。
- **SC-008**: 在不部署任何外部记忆服务、不新增长期记忆表或后端配置的前提下，用户可完成“保存偏好 → 重启/新会话 → 使用偏好回复”的完整流程。

## Assumptions

- 核心阶段的长期记忆以工作区为作用域；多租户、用户级或 Profile 级隔离属于扩展阶段治理能力。
- `.oryxos` 工作区由既有初始化流程创建，标准记忆文件与分区可由初始化或 Memory 首次装配补齐。
- 会话持久化、消息角色、历史上限、工具授权及审计链路复用前序能力，本特性不重新定义。
- Agent 是否保存一条信息由模型在 ReAct 过程中主动决定；本特性只保证显式调用后的持久化与召回行为。
- 长期记忆量在核心阶段保持小规模，按文件线性读取和包含匹配足以满足使用需求。
