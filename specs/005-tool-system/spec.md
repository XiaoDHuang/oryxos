## Clarifications

### Session 2026-08-25

- Q: 是否在第 20 节同时加入五个业界扩展工具? → A: 先完成技术方案定义的九个核心 Tool，`edit_file`/`grep`/`glob`/`ask_user`/`web_search` 明确延期，后续必须补充。

### Session 2026-08-26

- Q: Shell Tool 的固定超时是多少? → A: 按本次“继续”指令采用上次推荐的 30 秒，不新增配置字段；超时必须终止进程并返回明确失败。
- Q: Sandbox 的动作枚举以哪份文档为准? → A: 本次 plan 沿用已提出的技术方案三值契约：`FILE_ACCESS` / `SHELL_EXEC` / `HTTP_REQUEST`；不采用第 24 节示例的四值变体。
- Q: 真实白名单尚未实现时，临时安全实现能否默认开放工具? → A: `PermissiveSandbox` 仅用于测试；运行时默认拒绝外部动作，待第 24 节接入真实白名单后再开放。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 所有来源的工具使用统一契约 (Priority: P1)

作为 Agent 运行时维护者，我希望内置工具、Java 插件工具和外部 MCP 工具都以同一种契约注册和执行，
这样 ReAct 循环不需要判断工具来源，新增工具也不会扩大核心循环复杂度。

**Why this priority**: 统一契约是 Provider 暴露参数说明、Profile 精确授权和 ReAct 唯一执行路径的共同地基。

**Independent Test**: 遍历注册表中的所有工具，验证每个工具都有唯一名称、非空描述、非空参数说明，
并能返回包含成功状态、内容/错误和可重试信息的统一结果。

**Acceptance Scenarios**:

1. **Given** 内置、Java 插件和 MCP 三种来源的工具，**When** 注册完成，**Then** 调用方只看到同一种工具契约。
2. **Given** Profile 声明一个工具名称列表，**When** 查询该 Profile 的可用工具，**Then** 返回集合与声明恰好一致，不多不少。
3. **Given** 两个工具使用同一名称，**When** 尝试重复注册，**Then** 系统明确拒绝，避免静默覆盖。

---

### User Story 2 - Agent 使用核心内置工具操作外部世界 (Priority: P1)

作为 Agent 用户，我希望 Agent 能读取、写入和列出文件，执行受控命令，发起 HTTP GET/POST，
并把结果推送到通知目标，从而完成日常自动化任务。

**Why this priority**: 没有这些基础能力，Agent 只能生成文字，无法完成天气查询、文件处理和结果推送。

**Independent Test**: 每组工具都在临时目录或本地假服务中验证正常路径和越界路径；越界操作必须在产生外部副作用前被安全门拦截。

**Acceptance Scenarios**:

1. **Given** 一个允许访问的临时目录，**When** Agent 写入、读取并列出文件，**Then** 内容与目录结果正确。
2. **Given** 一个受允许的命令，**When** Agent 执行，**Then** 返回标准输出；命令失败、超时或不被允许时明确失败。
3. **Given** 一个本地 HTTP 服务，**When** Agent 发起 GET/POST，**Then** 返回响应；不允许的目标在请求前被拦截。
4. **Given** 当前 Agent 配置了通知目标，**When** 调用通知工具，**Then** 安全检查严格先于发送，结果走统一工具执行链。

---

### User Story 3 - 业务方通过 MCP 接入外部工具 (Priority: P2)

作为业务集成开发者，我希望通过配置一个标准输入输出模式的 MCP 服务，让其工具自动出现在统一注册表，
无需修改 ReAct 循环或为每个工具编写 OryxOS 专用代码。

**Why this priority**: MCP 是核心阶段扩展企业业务能力的主路径，必须做到外部依赖故障不拖垮 OryxOS 自身。

**Independent Test**: 使用 MCP 客户端替身返回工具列表并执行调用，验证名称、描述、参数说明和参数原样转发；
一个服务连接失败时，其余服务的工具仍正常注册。

**Acceptance Scenarios**:

1. **Given** 一个可连接的 MCP 服务，**When** 启动连接，**Then** 服务公布的每个工具被包装为统一工具并注册。
2. **Given** MCP 工具被调用，**When** 执行完成，**Then** 输入参数原样转发，响应转换为统一工具结果。
3. **Given** 一个 MCP 服务连接失败，**When** 系统启动，**Then** 记录可观测告警并跳过该服务，其他工具照常可用。

---

### User Story 4 - Java 插件工具自动接入 (Priority: P2)

作为 Java 业务开发者，我希望带工具声明的现有业务方法能被自动发现、生成参数说明并注册，
这样可以直接复用企业内的 Spring 服务，而不用手写第二套工具描述。

**Why this priority**: 这是三档 Plugin Tool 中集成最深的一档，适合已有 Java 服务但不能破坏统一执行链。

**Independent Test**: 给一个测试用 Java 工具方法，验证其名称、描述和参数说明被正确转换，执行结果进入统一结果模型。

**Acceptance Scenarios**:

1. **Given** 一个合法的 Java 工具方法，**When** 系统扫描注册，**Then** 注册表中出现对应统一工具。
2. **Given** Java 工具被执行，**When** 方法成功或抛错，**Then** 分别得到统一成功或失败结果，不绕过审计入口。

### Edge Cases

- 工具名称为空、描述为空或参数说明缺失时拒绝注册。
- Profile 引用了未注册工具时明确报错，不静默丢弃。
- 文件、命令、HTTP、通知、MCP 和 Java 插件的外部操作必须先进入安全检查；真实安全实现未就绪时运行时默认拒绝，测试显式注入替身，不得伪装成已具备隔离。
- 命令单次执行达到 30 秒后必须终止进程并返回失败，不能无限阻塞虚拟线程。
- HTTP 返回非成功状态、连接失败或响应过大时明确失败或按既定上限截断。
- MCP 工具重名、服务进程启动失败、返回非法工具描述或执行超时时，故障隔离到对应服务/工具。
- MCP 清单出现重复游标、分页/工具数量超限或发现总预算耗尽时，必须终止该服务发现、丢弃整批结果并继续其他服务；单次请求超时不能替代总预算。
- MCP 参数说明必须保留原始 Schema 的全部约束，包括根级组合关键字；不得因 SDK 类型字段有限而静默丢弃约束后注册。
- 敏感环境变量只传给声明它的 MCP 服务，不写日志或工具描述。
- 重试只针对被工具标记为可安全重放的网络断连、超时、MCP 临时故障、HTTP 5xx 等瞬态失败；已可能产生副作用且无法证明可安全重放的失败不自动重试。
- 参数错误、未知工具、Sandbox 拒绝和 HTTP 4xx 不重试；前置校验失败时实际 IO 次数为零。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 使用一个统一工具契约表达名称、描述、参数说明和执行操作，ReAct 循环 MUST NOT 根据工具来源分支。
- **FR-002**: 统一工具结果 MUST 包含成功标识、结果内容、错误信息和是否可重试；成功与失败必须能无歧义表达。
- **FR-003**: 工具注册表 MUST 拒绝空契约和重复名称，并能按 Profile 声明返回精确工具子集；未知名称必须明确失败。
- **FR-004**: 系统 MUST 支持把合法 Java 工具方法的元数据和执行行为包装成统一工具，MUST NOT 启用框架自动工具执行。
- **FR-005**: 核心文件工具 MUST 提供读取、写入、列目录三项能力，并在文件系统操作前调用统一安全检查位。
- **FR-006**: 核心命令工具 MUST 支持同步执行、固定 30 秒单次超时和失败输出，并在启动进程前调用统一安全检查位；超时必须终止进程，不新增超时配置字段。
- **FR-007**: 核心 HTTP 工具 MUST 支持 GET/POST、错误传播与响应上限，并在发出请求前调用统一安全检查位。
- **FR-008**: 通知工具 MUST 复用现有通知 Adapter，按当前 Profile 解析目标，并保证安全检查先于发送。
- **FR-009**: MCP 客户端 MUST 支持从配置启动多个 stdio 服务、获取工具列表、包装注册和转发执行；发现过程 MUST 有总耗时、分页和工具数量上限并拒绝游标循环，单个服务失败或超限 MUST NOT 阻断其他服务或 OryxOS 启动。
- **FR-010**: MCP 配置 MUST 支持服务名称、传输类型、启动命令和环境变量；核心阶段只接受 stdio 传输。
- **FR-011**: 所有工具执行 MUST 通过现有唯一执行入口并复用 `tool_invocations` 审计，MUST NOT 建立旁路执行或新审计表。一次逻辑调用（包含其内部重试）写一条最终审计，状态取真实最终结果，总耗时包含重试与退避。
- **FR-012**: 核心阶段 MUST 明确排除 Tool Policy、按需加载、MCP Server 暴露、容器级沙箱和同轮工具并行执行。
- **FR-013**: 唯一工具执行入口 MUST 只对标记为可重试的瞬态失败执行指数退避，首次调用后最多重试 3 次（最多 4 次实际执行）；确定性失败 MUST NOT 重试。该上限与 ReAct 默认 10 轮、可由 Profile 覆盖的外层上限相互独立。
- **FR-014**: 真实白名单交付前，运行时 MUST 默认拒绝外部动作，临时放行实现 MUST 仅存在于测试源码；不得增加生产绕过开关。
- **FR-015**: `tool list` MUST 保持轻命令与声明视图语义，不启动 Spring、不连接 MCP；真实注册表与执行能力由本节自动化 harness 验证。

### Deferred Requirements *(not part of lesson 20 acceptance)*

- **DR-001**: 第 22 节补齐长期记忆的保存与召回两个内置 Tool，并注册到同一工具体系。
- **DR-002**: 第 24 节以三值 `ActionType` 契约接入真实白名单，替换运行时默认拒绝，并对文件、命令、HTTP、通知、MCP 与 Java 插件的安全边界做最终验收；同步第 24 节课件四值示例偏差。第 20 节的测试放行不作为生产安全验收。
- **DR-003**: 核心九 Tool 完成后必须补充 `edit_file`、`grep`、`glob`、`ask_user`、`web_search` 五个扩展 Tool；实现前先同步 TechnicalSolution 与 AGENTS.md 的范围和交付节奏。

### Key Entities

- **统一工具**: 不感知来源的可执行能力，包含名称、描述、参数说明和执行操作。
- **工具结果**: 一次执行的统一结果，包含成功状态、内容、错误和可重试标识。
- **工具注册表**: 按唯一名称管理工具，并按 Profile 产生精确授权子集。
- **MCP 服务配置**: 外部 MCP 服务的名称、传输方式、启动命令和环境变量声明。
- **安全检查位**: 外部副作用前必须经过的统一接口；真实白名单策略在后续课程实现。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 注册表中 100% 的工具拥有非空且唯一的名称、非空描述和非空参数说明。
- **SC-002**: 对任意 Profile 工具声明，过滤结果与声明集合 100% 精确相等，不多不少；未知名称 100% 明确失败。
- **SC-003**: 文件、Shell、HTTP 和通知工具的测试均同时覆盖正常路径与安全检查先行路径。
- **SC-004**: MCP 工具的名称、描述、参数说明和执行参数 100% 原样映射；Schema 以原始 JSON 的结构语义为准，组合约束必须实际参与参数校验；单个服务失败、游标循环或超限不影响其他服务工具注册，失败批次新增工具数为零。
- **SC-005**: Java 插件工具无需修改 ReAct 循环即可注册和执行，框架自动执行路径为零。
- **SC-006**: 每次逻辑工具调用成功或失败都只经过一个执行入口，并产生一条对应最终审计记录；返回失败结果与抛异常均不得被审计为成功。
- **SC-007**: 自动化验收不访问真实外网、不启动真实企业 MCP 服务，所有外部依赖使用临时资源或替身。
- **SC-008**: Memory Tool、真实 Sandbox 和五个扩展 Tool 均有稳定 Deferred ID 与后续归属，不在第 20 节伪造半成品。
- **SC-009**: 可重试瞬态失败最多触发 4 次实际执行，确定性失败最多尝试 1 次，前置拒绝不得产生 IO；Shell 单次执行超时为 30 秒；ReAct 仍独立使用 Profile 的外层轮数上限（默认 10）。
- **SC-010**: 未注入真实白名单的运行时，外部动作执行次数为零；测试放行实现不进入生产 JAR。执行 `tool list` 时 Spring 启动次数、MCP 连接次数均为零。

## Assumptions

- 前序已提供 ReAct 循环、唯一 ToolExecutor、工具审计、Profile 工具列表和 Notify Adapter。
- 现有统一工具契约已包含名称、描述、参数说明和 JSON 文本执行入口；本节在兼容前序 Provider 的前提下补齐结果可重试语义。
- 核心阶段 MCP 只实现 stdio；SSE、远程认证和集群连接管理留到扩展阶段。
- 第 20 节仅在测试使用临时放行或受控替身验证正常链路；运行时默认拒绝外部动作，不宣称已经具备真实白名单隔离或可发布的外部工具能力。
- 第 18 节默认 Profile 包含尚未交付的 Memory Tool；本节不静默忽略它们、不创建假实现。第 20 节验收使用只声明本节已注册工具的独立 Profile，默认 Profile 待 DR-001 完成后恢复完整可用集合。
- Profile 的 `max_iterations=10` 只限制 ReAct 外层循环，不作为单个 Tool 的重试次数。
- 真 MCP server、真 Java 插件和真网络调用属于人工冒烟，不进入默认自动化测试。
