## User Scenarios & Testing

### User Story 1 - 查看并保留定时任务记录 (Priority: P1)

运维人员启动已配置的 Agent 后，能看到其任务、启用状态、下次触发时间及过往执行记录。

**Why this priority**: 先建立可恢复的任务身份与记录，后续执行管理才能有可信依据。
**Independent Test**: 登记一个任务、停用、保存一次执行，再重新打开同一数据目录；定义可更新，停用状态、次数及历史原样保留。
**Acceptance Scenarios**:

1. **Given** 合法规则首次启动，**When** 查看任务，**Then** 已启用、次数为零、下次时间在未来，无执行历史。
2. **Given** 已停用且有历史，**When** 重启，**Then** 仍停用、历史与次数不变。
3. **Given** 规则从文件移除或不合法，**When** 重启，**Then** 不自动执行，既有记录保留且明确显示当前不可运行。

### User Story 2 - 自动执行与人工控制 (Priority: P1)

任务到点自动走与人工对话相同的处理链。运维人员可以立即补跑或停止后续自动触发。

**Why this priority**: 使任务既能持续执行，也能在故障或临时需要时被控制。
**Independent Test**: 运行、停用、自动跳过、停用状态下手动执行、失败后再执行；逐次核对结果与计数。
**Acceptance Scenarios**:

1. **Given** 已启用任务，**When** 连续触发两次，**Then** 复用同一调度会话，增加两条执行记录及两次计数。
2. **Given** 已停用任务，**When** 到达触发点，**Then** 不调用 Agent、不增加历史；立即执行仍可运行一次。
3. **Given** 同一任务或同一 Agent 的调度执行尚未退出，**When** 再次触发，**Then** 自动触发跳过，手动请求明确报忙，不排队重复运行。
4. **Given** 通知被拒绝或模型失败，**When** 本轮结束，**Then** 留失败记录、不给出推送成功结论，后续触发仍可运行。

### User Story 3 - 在管理台完成操作 (Priority: P2)

运维人员在与官网一致的管理台查看任务与分页历史，执行补跑或启停，并看到操作结果。

**Why this priority**: 提供可用的运行操作面，免去直接修改运行数据。
**Independent Test**: 从页面完成查看、执行、停用、查看失败历史；刷新后显示真实状态。
**Acceptance Scenarios**:

1. **Given** 有任务，**When** 进入定时页，**Then** 看见 Agent、规则、下次时间、上次结果、次数与状态。
2. **Given** 一次操作在处理中，**When** 再次点击，**Then** 不重复提交；失败明确显示，执行请求不自动重试。
3. **Given** 空数据、加载中、网络错误，**When** 页面渲染，**Then** 分别显示占位、加载提示或重试入口；窄屏仍可操作。

### User Story 4 - 重启和多 Agent 场景仍正确 (Priority: P2)

维护者停止并重新启动应用后，已完成的数据不丢失；两个 Agent 的工具、会话和调度互不混淆。

**Why this priority**: 证明运行记录可恢复，单个任务故障不会拖住整个底座。
**Independent Test**: 独立进程执行后终止重启，核对会话、记忆、审计、任务记录，并让两个差异 Agent 交替执行。
**Acceptance Scenarios**:

1. **Given** 已完成对话、记忆和调度，**When** 终止并重启，**Then** 全部已完成记录可查、计数未归零，启用规则从未来时间继续，不补跑停机期间触发。
2. **Given** 任务执行中进程终止，**When** 重启，**Then** 明确标记执行结果未知，不伪报成功或自动重放副作用。
3. **Given** A 仅文件工具、B 仅 HTTP 工具，**When** 交替调用且 A 调度失败或阻塞，**Then** 模型看到的工具与会话分离，B 仍能开始和完成。

### Edge Cases

- 任务 id 全局唯一；同 id 换 Agent 拒绝登记，旧记录保留；重复 id 的后续规则跳过并记日志。
- 停用不取消已开始执行；同值启停幂等；移除的规则保留记录但不能补跑或启用，恢复原规则可重新登记。
- 达到最大对话轮数、工具失败被模型解释成普通文本、完成后记账失败，都不能当作成功执行。
- 超时发出取消并报告失败；执行线程未退出前保持占用，不宣称已回滚发生过的外部副作用。
- 时间统一可比较且带时区；采用规则指定时区；历史同一时间的记录仍有稳定顺序。

## Requirements

### Functional Requirements

- **FR-001**: 启动时从既有 Agent 配置登记合法规则；保留全局规则身份校验、显式时区和错误隔离。
- **FR-002**: 任务定义快照、启停状态、次数、最近结果、下次时间及执行历史必须持久保存，旧数据升级与重复启动不丢记录。
- **FR-003**: 登记不得重置既有启停和历史；配置移除/失效保持历史并禁止执行，同 id 不得静默迁移到另一 Agent。
- **FR-004**: 启用任务自动触发，停用任务自动跳过且零历史；立即执行无视启停，但须为当前合法登记规则。
- **FR-005**: 同任务和同 Agent 的调度执行不得重叠；自动冲突跳过、手动冲突报忙；不同 Agent 不因单任务阻塞而串行等待。
- **FR-006**: 调度与人工共用处理链；同 Agent 连续调度复用固定调度会话，成功失败的模型与工具调用继续留审计。
- **FR-007**: 每次实际执行记唯一历史；正常完成且本轮所有工具成功才记成功，模型异常、工具失败、轮数耗尽、超时或结果未知均明确区分；不得从模型答复文本猜成功。
- **FR-008**: 开始记录与次数原子更新，每次实际开始只累计一次；执行终态与任务最近状态原子更新，不重复计数。持久化失败可观测，不能将落库失败报告为成功。
- **FR-009**: 提供任务列表、分页执行历史、立即执行和启停四种操作；未知任务、忙碌、不可运行和非法输入返回明确错误。
- **FR-010**: 管理页提供任务列表、历史和真实运行/启停操作，遵守官网视觉；原有五页只读，具备三态、操作中防重入和窄屏适配。
- **FR-011**: 已完成会话、记忆、调用审计、任务状态与历史跨进程重启保留；在途执行恢复后标记未知，不补跑停机周期、不自动重放。
- **FR-012**: 两个 Agent 的工具集、会话与定时规则互不串用；无多租户隔离承诺，长期记忆仍按既有工作区共享。
- **FR-013**: 单次 Agent 执行按既有 60 秒上限报告超时并发出取消；超时不导致下一次与未退出的执行重叠；外部 MCP 不可达不阻断健康能力启动。
- **FR-014**: 天气推送必须使用本次查得的天气；成功场景一次查询、一次通知和三轮模型响应，测试接收端实际收到；拒绝通知场景保留失败审计且后续触发可用。
- **FR-015**: 涉外调用沿用白名单、密钥注入与审计；错误文本不泄漏凭证；验证使用隔离环境，部署 Demo 的真实渠道条件独立记录。

### Key Entities

- **定时任务**：全局稳定 id、所属 Agent、规则快照、启停、下次时间、最近执行时间/状态、累计次数；可区分历史保留与当前可运行。
- **任务执行**：唯一执行 id、所属任务、调度会话、开始时间、成功/失败/进行中或未知、可读错误与耗时。
- **既有会话与审计**：由统一运行链写入，任务历史引用会话，不另建对话模型。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 一个新任务完成登记、执行、查询、停用全流程；两次完成产生恰好两条历史与两次计数，停用自动触发零增量。
- **SC-002**: 重启前已完成的五类记录全部恢复；停用仍停用、次数不归零；在途执行不会变为成功或被自动重放。
- **SC-003**: 天气通知内容可关联本次天气；两次触发复用一个调度会话，每次一次查询和一次推送；失败一次后仍可再次触发。
- **SC-004**: 两个不同 Agent 的工具/会话/调度隔离测试全部通过；其中一个持续阻塞时另一个仍能在首个超时前完成。
- **SC-005**: 桌面与 375px 窄屏均完成四种管理操作并显示三态；点击处理中不重复发送，刷新后与持久记录一致。
- **SC-006**: 超时调用在 60 秒上限触发取消和超时报告，不能继续发起后续工具；未退出线程保持忙碌保护；错误不使下个健康触发失效。

## Assumptions

- 单实例内网运行，认证/治理维持既有阶段边界；本节不引入分布式锁、队列、可视化编排或通用任务定义 CRUD。
- 历史默认不删除；分页默认 20、上限 100；缺省部署规模沿用十个 Agent，长期容量优化不属于本节。
- 一次“成功”表示执行链正常结束且工具最终结果均成功，不保证模型语义正确；真实天气与通知内容单独验收。
- 核心记忆默认仍是文件；任务状态/历史持久化不代表默认记忆后端切成数据库。
- 60 秒后的取消是协作式；不声称强制终止任意第三方代码或撤销已经发生的外部操作。实现必须验证受控 Provider/Tool 取消行为。
- 课件提及的企业通知、新闻源与 MCP 配置按实际部署方提供；测试 webhook 不等于企业渠道验收。
